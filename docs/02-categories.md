# 02 · 服务类目

类目选错，后面怎么改都过不了。功能不在个人开放清单里，改多少遍都过不了。

## 一、官方规则原文

《常见拒绝情形》2.1：
> 小程序服务类目所对应的页面中的核心内容必须与该类目一致。
> 必须保证用户在该页面能使用该服务类目，不得隐藏，不得进行多次跳转。

《常见拒绝情形》2.1.3：
> 你需根据实际提供服务范围慎重选择服务类目，一旦你选择了游戏类目，该类目将不可修改变更为其他小程序类目。

《常见拒绝情形》3.1.2：
> 小程序所提供的所有服务类目功能，必须在小程序首页得到体现，即在小程序首页必须能直达或者**经过 2 次点击到达**所有提交的服务类目页面。

三条合起来看，类目等于一个入口承诺。 你填了「图片处理」，审核员就要在首页 2 次点击内找到图片处理功能，而且那个页面必须真的能处理图片。

## 二、个人主体开放的类目（全部）

这是完整清单，不在里面的就是没有：

```
物流服务    查件 / 装卸搬运
教育服务    教育信息展示（不支持视频播放/直播/课程销售）
交通服务    代驾
生活服务    丽人 / 婚庆 / 家政
餐饮服务    餐厅排队（不含线上点餐、外卖）
旅游服务    出境WiFi
工具        记账 / 日历 / 天气 / 办公 / 图片处理 / 计算器 /
报价比价 / 信息查询 / 预约报名 / 健康管理 / 备忘录
商业服务    律师 / 企业管理 / 会展 / 公关推广 / 环保回收 / 摄影扩印
体育        体育培训 / 在线健身
```

**明确没有的**：游戏、电子娱乐、卡牌、文字冒险、社交、社区、论坛、直播、笔记、问答、资讯、电商平台。

个人主体做带游戏玩法的小程序，属于既无对应开放类目、又易触碰社交/游戏边界的高风险行为。要做游戏必须走小游戏体系，不是小程序工具类目。

## 三、两个写在文档里但很少人看的边界

这两条是「工具」类目最容易踩的坑：

**图片处理**
> 仅限制作、剪辑，**无传播分享 / 公开访问**

**备忘录**
> 不涉及用户原创内容的传播及公开访问

**边界条款原文**
> 如提供传播和公开访问服务，属于社交范畴，需选择【社交-笔记】类目。

推论：
- 你的图片工具如果带「作品广场」「一键分享到社区」「他人可见」，就越界了
- 你的备忘录如果带「公开笔记」「共享给他人」，就越界了
- 而「社交-笔记」类目，个人主体拿不到

所以个人主体的工具类小程序，天花板是：功能自用，内容不外流。

这一条和 5.18 内容安全是同一件事的两个面：内容一旦能传播出去，平台就要求你管内容；而管内容要后端接口；要后端接口就不是零成本。

## 四、5 个槽位：占满之后怎么办

后台原文：
> 服务类目**最多添加 5 个**，本月可添加 3 次

两条限制是分开的：**槽位数量**和**本月修改次数**。很多人只看到后者。

槽位占满后，想加新类目必须先删一条旧的。删了再想加回来，要等下个月的次数。

占满后的唯一处置：hide 掉那个功能，不能靠加类目解决。

```
某个功能被审核问询  →  hide 掉该功能，重新打包
→  不是「去后台加个类目」
```

## 五、类目落位：一个功能必须恰好归一个类目

如果小程序有几十个功能（工具类常见），要建一张落位表。

**必须满足三个条件**（任一不满足，后台自检会报红）：
1. 每个可见功能必须有类目归属
2. 类目必须在个人可选清单内
3. 表里不能有多余项（功能已 hide / 删除但表里还留着）

最容易犯的错：拿产品自己的导航分组当类目。

产品导航分组（「压缩瘦身 / 格式转换 / 计算助手」）和微信类目（「图片处理 / 计算器 / 办公」）是两套名字。前者是你自己分的，后者是平台认的。用前者去对后者的账，永远对不上。

落位判断的三个真实分歧点（供参考）

| 功能 | 容易错归 | 应归 | 理由 |
|---|---|---|---|
| 图片信息查看（EXIF） | 信息查询 | 图片处理 | 处理的是图片本身 |
| 图片配色提取 | 信息查询 | 图片处理 | 同上 |
| 亲戚称呼计算器 | 计算器 | 信息查询 | 本质是查一张对照表 |
| 尺码换算 | 计算器 | 信息查询 | 同上 |
| 日期间隔计算 | 日历 | 计算器 | 算的是差值，不是日历 |
| 随机数生成 | 办公 | 计算器 | 计算行为 |

判断口径：看这个功能在干什么，不看它长得像什么。

## 六、提交前自查

```
□ 核心功能能在个人开放类目清单里找到一行
□ 每个已填类目，首页 2 次点击内能到达对应功能页
□ 对应页面能真的完成该类目的服务，不是空壳
□ 没有出现「传播 / 分享 / 公开访问 / 他人可见」这类越界功能
□ 后台已填类目数 ≤ 5，本月剩余修改次数已确认
□ 功能落位表：每条功能恰好出现一次（不是总数对就行）
```

最后一条是踩过的坑：只验总数会挡住重复+遗漏这对组合。 两条错互相抵消，总数还是对的。
