# 05 · 内容安全（5.18）

这一份最贵。里面每一条都是拿一个真实账号换来的。

## 一、先分清两种处置

平台对内容安全有**两种**动作，很多人混成一件事：

| | 提醒（预警） | 处理（限制） |
|---|---|---|
| 措辞 | 「**极有可能**违反 5.18」 | 「未设置过滤机制」 |
| 性质 | 预警 + 限期整改 | 已处罚 |
| 后果 | 给一个精确到秒的死线 | 五项**永久限制** |
| 能否挽回 | 整改 + 回复说明 | 只能申诉 |

**先收到提醒，整改不到位，才变成处理。** 所以收到提醒时还有救。

## 二、提醒通知原文（认准它）

```
小程序存在信息安全风险的提醒

你好，经平台验证，你的小程序对违法违规等不当信息的过滤机制不够完善，
极有可能违反《微信小程序平台运营规范》5.行为规范-5.18内容安全等相关规定。

风险内容：查看详情

平台建议：
1. 请接入并调用内容安全检测接口校验文本/图片是否含有敏感内容……
2. 请排查删除小程序中已存在的违规内容……

平台会对你的小程序再次进行信息安全风险评估，如果在 YYYY-MM-DD HH:MM:SS 前
仍然存在信息安全风险，平台将会停止向你的小程序提供"被搜索、内容分享、二维码打开"等服务。
```

**三个关键理解**
- 「极有可能违反」= 预警，不是已处罚
- 处理是「停止服务」，不是封禁
- **死线是精确到秒的时间戳**，会写进通知。错过就真停

## 三、处理通知原文（5.18 落地版）

- 被处理原因：**未设置过滤违法、违规等不当信息内容的机制**
- 违反规则：《微信小程序平台运营规范》5.行为规范-**5.18 内容安全**
- 处理内容（**每一项都写着「永久限制」**）：

```
1. 小程序内容分享
2. 被搜索
3. 跳转其他小程序
4. 通过短链接打开小程序
5. 通过二维码打开小程序
```

- 触发方式：**「因用户投诉并经平台审核」**
- 通知末句：「如已完成整改，可点击申诉。申诉通过后被封禁的服务会恢复使用」

**五项全封 = 新用户基本进不来。** 只剩「我的小程序」列表和历史使用记录。
**账号 ≈ 沉没成本，能迁移的是代码资产。**

## 四、5.18 条款原文与高危名单

官方运营规范 5.18：
> 小程序涉及未设置过滤违法、违规等不当信息内容的机制。必须调用内容安全检测接口
> 校验文本/图片是否含有敏感内容……包括但不限于：
> 5.18.1 UGC 平台类 / 5.18.2 昵称测试算命类 / 5.18.3 抽奖类
> **处理规则**：一经发现将根据违规程度对该小程序**阶梯封禁**分享能力、
> 朋友圈二维码打开能力和限制单页面处理。

**官方《内容安全解决方案》点名的高危场景：**
> 用户自定义头像检测、**涉及拍照的工具类应用（如 P 图，自拍类应用）用户拍照上传检测**；
> 电商类商品上架图片检测；媒体类用户文章里的图片检测等。

**→ 做图片处理工具 = 在名单上。** 这不是运气问题，是类目问题。

## 五、⭐ 平台安全模型的三个「不看」

这是最反直觉、也是最多人栽的地方：

```
① 不看语义
   "只有他自己看得见" —— 没用

② 不看是否上传
   本机处理、不存服务器 —— 全都不豁免

③ 只看链路
   「用户内容 → 视图节点」这条链存在，且链上没有检测机制 = 风险
```

**所以「本机处理、不上传服务器」不构成任何豁免。**

踩过的坑：当初的判断是「盲处理（用户图永不绑视图节点、结果只进相册）能躲过 5.18」。
实际只成立一半：
- ✅ 挡住了「站内展示/内容流」这一面
- ❌ 没挡住「**生成物离开 App**」这一面

违规样本落在**「图片水平镜像」**——纯几何翻转、零文字输入。这一条直接证伪了「只有文本入图功能才会生产内容」的判断。

## 六、⭐ 产品设计第一个分岔口

在写代码之前先回答这个问题：**你的产出里，有没有「必须给用户看的用户内容」？**

| 产品 | 产出里有必须展示的用户内容吗 | 结果 |
|---|---|---|
| 图片压缩工具 | ❌ 没有（压缩不需要看图） | **砍掉展示入口 → 逃出坑 → 成本 0** |
| 拼豆图纸转图 | ✅ 有（图纸就是产出） | **砍不掉 → 只能交入场费** |

**有 → 268.8 元/年 + 人工审核队列，是入场费，绕不开。**
**没有 → 移除展示入口是最干净的解法，功能一点不少。**

### 移除展示入口的具体做法

```
删掉所有渲染用户内容的视图节点：
  <image src="{{userContent}}">
  wx.previewImage
删掉全屏查看能力
结果区只显示数值（像素尺寸、格式、文件大小）
```

**关键技巧**：原始数据可以**保留在 data 里**（作为管线的内部输入），
只要**不绑定到任何视图节点**就不算展示。功能 100% 不变。

配套动作：
- 唯一的文本输入框加数字过滤：`replace(/[^0-9]/g,'')`，输入层面锁死为数值
- 关于页补一句「为什么看不到图片」——把「不展示」变成产品说明，不是缺陷

## 七、真要接入检测：技术事实

### 两个接口，只有一个能用

| 接口 | 类型 | 状态 | 关键特性 |
|---|---|---|---|
| `security.imgSecCheck` | 同步 | ⚠️ **1.0 版，2021-09-01 停止更新** | 接受二进制流，不需要公网 URL —— 最想要的特性，但已死 |
| `security.mediaCheckAsync` | 异步 | ✅ 2.0，唯一在维护的 | **必须公网 URL**，结果异步回调 |

**→ 没有「直接传 buffer 就能检测」的活路。图片必须出手机。**

### `mediaCheckAsync` 硬约束

| 项 | 要求 |
|---|---|
| 调用位置 | **「应在服务器端调用，不可在前端直接调用」** |
| 云调用 | ✅ 支持（`security.mediaCheckAsync`），免 access_token |
| `media_url` | **必须是可被检测服务器下载的公网 URL**（错误码 `-1008` = 下载错误） |
| `media_type` | 1=音频；2=图片 |
| `scene` | 1 资料；2 评论；3 论坛；4 社交日志 |
| `openid` | **必填**，**「用户需在近两小时访问过小程序」**（错误码 `61010` = 访问记录超时） |
| 文件限制 | 单文件 ≤ 10M；jpg/jpeg/png/bmp/gif |
| 频率 | 2000 次/分钟，200,000 次/天（单 appId） |
| 结果推送 | 异步，官方写「30 分钟内」推送到消息接收服务器 |

**返回三态**
- `suggest`: `risky` / `pass` / `review`
- `label`: 100 正常；20001 时政；20002 色情；20006 违法犯罪；21000 其他

⚠️ **`review` 需要人工确认** —— 官方原文：「API 判断为 REVIEW 的内容，说明可能存在风险，**需要人工确认**」。
**这就是「持续的活」的来源。**

### ⭐「30 分钟」是吓人的，实际秒级

实测 200 次（微信正式环境，网络稳定）：

| 图片大小 | 平均响应 | 最快 | 最慢 |
|---|---|---|---|
| < 100KB | **2.8 秒** | 1.2 秒 | 7.5 秒 |
| 100-500KB | **5.1 秒** | 2.4 秒 | 12.3 秒 |
| 500KB-1MB | 8.7 秒 | 4.6 秒 | 18.9 秒 |
| > 1MB | 12.4 秒 | 7.8 秒 | 23.1 秒 |

**→「30 分钟」是最坏情况上限，不是常态。**
**→ 上传前先压缩（`wx.compressImage`），越小越快。**
**→ 不必送原图，长边压到 512px 再送。违规特征在缩略图上一样看得出来。**

### 前端拿不到用户图片的公网 URL

`wx.chooseMedia` 返回的是**本地临时路径**（`wxfile://...`），检测服务器下载不到。

变公网 URL 只有两条路：
1. `wx.cloud.uploadFile` 传到云存储 → **必须开云开发**
2. 自建服务器（个人主体没有，且域名要备案）

### 成本：268.8 元/年 + 一次性的活

```
微信认证          30 元/年
云开发            19.9 元/月 × 12 ≈ 238.8 元/年
─────────────────────────────────────
合计              268.8 元/年
```

云开发计费官方原文：
> 自 2025 年 2 月 19 日起，每个没有云环境或云环境已注销超过 1 个月的小程序账号，
> 可创建一个**免费云环境**；
> 免费云环境在小程序**未发布上线阶段**，无需开发者续费；
> 免费云环境在小程序**发布后，环境的到期时间变更为上线后的第 15 天**。

**→ 免费额度是「开发期免费」，上线 15 天后开始收费。这是持续成本，不是一次性的。**

按量单价：调用 0.5 元/万次；容量 0.1 元/GB/日；云函数 0.00011108 元/GBs
**→ 单次「上传+检测+下载」≈ 0.004 元，19.9 元/月可支撑约 5 万次。**

内容安全接口本身不额外收费。**要花钱的只有「图片出手机」这一段。**

### 接入步骤

```
1. mp 后台 → 开发 → 云开发 → 开通（个人主体可开，有免费额度）
2. 新建云函数 secCheck，调 security.mediaCheckAsync（云调用，免 access_token）
3. 流程：选图 → wx.compressImage 压缩 → wx.cloud.uploadFile → 云函数送检
4. 配消息接收（云函数）收异步回调
5. pass → 渲染展示；risky → 拒绝；review → 人工确认
6. 检测完的临时文件立即删除
7. 隐私指引补声明「上传图片用于安全检测」
8. 关于页的隐私承诺要改（"不联网、不上传"当场作废）
```

**必须提前知道**
- ⚠️ 需要登录态（接口要 `openid`）→ 不能纯匿名
- ⚠️ 上线后 19.9 元/月
- ⚠️ review 分支要人工看 = 持续的活
- ⚠️ 异步接口能否满足「渲染前拦截」，官方无明文 → 拿不准就问平台

## 八、三条路，没有第四条

```
路 A：移除展示入口
  → 成本 0，功能不变，只适用于「看图不是刚需」的产品

路 B：真接入检测
  → 268.8 元/年 + 人工审核队列，产品必须展示用户内容时唯一选择

路 C：不管
  → 停「被搜索」→ 产品死
```

## 九、整改回复文案（可复用）

```
关于《小程序存在信息安全风险的提醒》的整改说明

收到贵方 YYYY-MM-DD 关于内容安全（运营规范 5.18）的风险提醒后，
我们已对小程序进行全面排查，并完成整改。现说明如下：

一、小程序性质：无 UGC 场景
本小程序是一款纯本地图片压缩工具，不提供任何用户内容发布、传播功能：
无评论、无发帖、无聊天、无社区、无昵称设置、无资料编辑，用户之间不存在
任何内容传播链路，小程序内也不存在任何面向他人公开展示的用户内容。

二、已完成的具体整改
1. 移除用户内容的展示入口（重点）
   原版本在页面中直接渲染用户选中的图片，并支持全屏查看。
   整改后已彻底移除该展示入口：页面不再渲染任何用户提供的图片，
   仅呈现由程序计算得出的数值信息。同时移除了全屏看图能力。
   小程序内现已不存在任何承载用户内容的视图节点。

2. 约束唯一文本输入为纯数值
   小程序内唯一的文本输入框为目标文件大小，已限定为数字类型，
   并在输入处理中强制过滤非数字字符，在输入层面即无法录入文字。

3. 排查并确认无遗留违规内容
   本小程序无服务端、无数据库、无云存储，图片处理全程在用户设备
   本地内存中完成，不产生也不留存任何用户内容或测试数据。

三、实际效果
整改后，小程序内不存在用户内容的展示、存储与传播。

四、后续说明
本小程序确无 UGC 场景，故未接入内容安全检测接口。
若平台认为仍需补充其他技术措施，请明确告知具体场景与要求，
我们将按要求配合完成。
```

### ⚠️ 三条禁忌（踩过）

1. **不要写「已接入内容安全接口」** —— 没接就是虚假陈述
2. **不要写「不收集任何数据」** —— 与隐私指引里声明的「采集用户隐私」冲突
3. **不要把「图片仅在本机处理」当合规依据** —— 平台不认这个，认的是「有没有检测机制」

## 十、申诉三段式（已被处理时用）

### 第一段 · 摆事实，给可核验的东西

```
本小程序零网络调用，后台服务器域名四项全空，平台可自行核验，
运营方从未获得任何图片。
```

说「平台可自行核验」，不要说「我说的都是真的」。

### 第二段 · 说明扩散链路已不存在

```
输出只写用户本机相册，且分享/短链/二维码/跳转已被封，
扩散链路已不存在，继续封「被搜索」惩罚的是获客不是违规。
```

### 第三段 · 把整改方向变成向他们要口径

```
愿继续收紧可写入用户文字的功能，但接入识别接口需上传用户图、
与已公示的「不上传服务器」隐私指引直接冲突，
请平台明确「不采集图片前提下可接受的整改方式」。
```

**第三段是整个申诉最关键的一段。** 它把「我怎么改」变成「你告诉我怎么改」。
就算不解封，也能拿到一句可执行的官方答复——**那句话本身就是资产**。

### 申诉硬规则

```
□ 申诉入口两次不通过即关闭 —— 不要拿猜测去试第一次
□ 第一次申诉前，把能核验的事实准备齐（后台截图、域名配置截图）
□ 第二次必须有新增证据，不能重复同一套说法
□ 申诉期间不要改动小程序任何配置
```

## 十一、不确定就问平台（别猜）

入口：微信开放社区「安全中心专区」

```
问题1：用户在小程序端选择本地图片，经本地压缩后上传至云存储，
       调用 security.mediaCheckAsync 检测，检测通过（约 3-10 秒）后才渲染展示。
       该流程是否满足 5.18 内容安全要求？

问题2：用于检测的图片为压缩后的缩略图（长边 512px 内），是否可接受？
       是否有最小分辨率要求？

问题3：检测产生的临时图片在检测完成后即删除、不做任何留存，是否符合规范？

问题4：security.imgSecCheck（同步接口）标注 2021-09-01 停止更新，
       是否仍可用于线上？是否有替代的同步检测方案？
```

## 十二、事前预防清单（比申诉有用一百倍）

```
□ 用户要上传内容吗？
    否 → 干净，继续
    是 → 往下
□ 产出里有「必须展示的用户内容」吗？
    否 → 走路 A：移除展示入口（成本 0）
    是 → 往下
□ 接受 268.8 元/年 + 人工审核队列吗？
    否 → 换产品形态
    是 → 走路 B：真接入检测
```

**任何一项是「有」，都要在提审前想清楚。三条路里没有第四条。**
