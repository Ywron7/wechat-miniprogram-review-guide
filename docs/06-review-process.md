# 06 · 提审节奏与表单

提审不是「提交然后等」。表单填错、节奏错了，会白排好几次队。

## 一、实测时长（比官方承诺快得多）

| 环节 | 官方承诺 | 实测 |
|---|---|---|
| 名称审核 | 7 个工作日 | **当天驳回 / 当天通过** |
| 代码审核 | 1~7 个工作日 | **53 分钟**（14:15:40 提审 → 15:08:39 上线） |
| 加急审核 | 2 小时内 | **2~12 小时** |
| 备案 | 7~20 个工作日 | 这是整条链最长的一段 |
| 微信认证 | 15 个工作日内 | 交 30 元，约 1 天 |

**推论：一次迭代 ≈ 半天。** 你有充足的重试机会，但每次重试都要重新排队。

**审核员工作时间**
- 个人主体：**9:00 - 21:00**
- 非个人主体：9:00 - 24:00
- 周末节假日有少量值班

**提交时机**：工作日早上 9~11 点提交，当天出结果概率最高。晚上提交等于多等一夜。

## 二、加急审核：个人主体每年只有 1 次

```
个人主体      1 次/年
非个人主体    3 次/年
```

（网上大量文章写「3 次/年」，那是**非个人主体**的口径，别照着算。）

**什么时候用**
```
❌ 不用在第一次提审上
—— 卡住你的通常是备案，不是审核速度。审核过了也发不出去

✅ 用在两个场合
① 内容安全整改的死线快到了，等不起
② 上线后发现严重 bug，要紧急修
```

## 三、发布 = max(代码审核过, 备案过)

这条公式决定了你的排期：

```
发布上线时间 = max(代码审核通过时间, 备案通过时间)
```

**所以备案是唯一真正的瓶颈。** 代码审核再快，备案没过也发不出去。
反过来，备案在跑的时候，代码审核可以并行做，互不影响。

```
代码审核 / 内容安全  →  影响「能不能上线、能不能被搜到」
ICP 备案            →  影响「能不能上架发布」
微信认证            →  影响「有没有被搜索/被分享能力」
```

**三条都过，产品才真正跑起来。**

## 四、提审表单：7 个字段逐项

| 字段 | 填什么 |
|---|---|
| **版本描述** | **必填**，200 字内。见下方模板 |
| **图片预览** | 选填，但强烈建议传 3~5 张真机截图 —— 审核员一眼看懂这是干什么的，能少一轮「功能不明确」的驳回 |
| **视频预览** | 跳过 |
| **测试账号** | 不需要登录 → 选「无需登录账号即可使用」；有账号体系 → **必须给能体验全部功能的测试号** |
| **小程序订单中心 path** | 跳过（这是交易类小程序用的） |
| **审核加急** | ⚠️ 建议「请选择」不选，留着（见第二节） |
| **用户隐私保护指引设置** | ⚠️ **必须选「采集用户隐私」**，千万别选「未采集」（见 04 文档第九节） |

### 版本描述模板

```
首次提交。
图片压缩工具：输入目标大小（如 100KB），自动压缩到不超标，无需手动试参数。

功能点：
1. 目标大小压缩——输入上限值，自动计算最优压缩参数
2. 支持固定尺寸 / 保持比例两种模式
3. 压缩前后体积对比预览
4. 一键保存到相册

图片仅在本机处理，不上传服务器。
```

约 135 字。最后一句要和隐私指引里的措辞一致，别改成「不收集数据」，会跟隐私声明打架。

### 其他表单字段（会遇到但不重要）

- **适龄提示**：显示「审核中」不影响版本提审，微信会合并流转
- **版本更新提醒**：选填，首发无老用户订阅，留空
- **宣传图**：选填，留空，不卡审核
- 苹果开发者账号（AppleID）：出现红字 `! 请输入AppleID` 是表单非空校验。
**不用花钱、不需要苹果设备** —— 直接填你的常用邮箱（如 `xxx@qq.com`）即可，前端只做格式校验。
想正式注册就去 `appleid.apple.com/account` 免费注册（0 元，无需苹果设备）。
- App Store 游戏名称 / 下载链接：留空

## 五、截图规范（被驳过两次的坑）

### 驳回原文

```
所提供的图片质量差，无法辨识图内文本内容
```

**原因**：脚本自动截的预览图分辨率偏低（518×920 标清），审核后台压缩后小字边缘发虚，
触发平台 OCR 的清晰度阈值。

**改法**：在开发者工具或真机**直接原画质高清截图**。

### 三条硬规则

```
① 每个槽位必须是不同的图
微信后台有哈希查重，跨模块复用同一张会被抓

② 单张 60KB ~ 5MB
手机真机截图或开发者工具高清截图天然符合

③ 顶栏名称要清晰可辨
审核员要靠它确认「这个截图属于这个小程序」
```

### 8 张截图的标准分工（以游戏为例）

```
模块一 · 各主要场景（3 张）
1. 主界面大厅（带顶部名称、核心操作按钮）
2. 关卡/地图界面
3. 设置或特色模式界面

模块二 · 玩法（3 张）
4~6. 三个不同关卡的实际游玩中界面

模块三 · 系统功能（2 张）
7. 货币/结算界面
8. 商城/图鉴界面
```

**工具类小程序的对应做法**：首页空态 → 选图后 → 处理中 → 结果对比 → 保存成功，各一张。

⚠️ 示例图不要带其他 AI 工具的生成水印（比如右下角「豆包AI生成」）。审核员不需要多余的解释空间。

## 六、提审之后，什么都别动

**铁律**：提审之后到出结果之间，不动名称、不动简介、不动类目、不动 logo、不重新上传代码。

改任何一项都可能触发重新审核，而重新审核不保证通过。你已经等了一天，别在最后一天动它。

官方只写了这一句，但后果很重：
> 备案信息与小程序信息不一致时，平台可警告、封禁功能、强制注销备案。

### 一个容易点错的地方

后台「审核版本」那一栏，如果挂着一个旧版本状态是「**审核通过待发布**」：

```
✅ 它不挡新版本提审（挡提审的是「审核中」）
❌ 别点它的「提交发布」 —— 那是把同一份旧代码再发一次，白占发布次数
```

## 七、驳回之后怎么办

```
收到驳回
↓
读驳回理由原文（逐字读，不要猜）
↓
判断属于哪一项：名称 / 类目 / 备案 / 隐私 / 内容安全 / 完成度
↓
只改这一项，不要顺手改别的
↓
重新上传代码（如果改的是代码）
↓
重新提审
```

**关键：一次只改一项。** 一次改五项，下次驳回你不知道是哪一项没过。

### 常见驳回理由对照表

| 驳回原文 | 属于哪一项 | 去哪看 |
|---|---|---|
| 涉及营销商业化词，命名不规范 | 名称 | `01-naming.md` |
| 涉及以通用词命名 | 名称 | `01-naming.md` |
| 服务类目与实际服务不符 | 类目 | `02-categories.md` |
| 涉及 XXX，请补充 XXX 相关类目 | 类目 | `02-categories.md` |
| 未设置过滤违法、违规等不当信息内容的机制 | 内容安全 | `05-content-safety.md` |
| 功能不完整 / 无法正常体验 | 完成度 | 本文第八节 |
| 缺少隐私政策 / 未授权即收集信息 | 隐私 | `04-privacy.md` |
| 实际提供的服务属于尚未开放的服务类目 | 类目 | `02-categories.md` |
| 所提供的图片质量差，无法辨识图内文本内容 | 提审材料 | 本文第五节 |

## 八、提审前必须是一个「完成品」

《常见拒绝情形》3.3-1：
> 提交的小程序须是一个完成品，要求可以打开，可以运行，且不可以是一个测试版。
> 示例：不可运行、存在崩溃、闪退、按钮没有响应、文字表述不完整等。

3.3-4：有账号体系须提供测试号（账号 + 密码，可体验所有功能）。
3.1-5：功能应具有使用价值，不能过于简单（只有一个页面一个按钮）。

**三条硬要求**
1. 不能有「即将上线」「敬请期待」「功能开发中」字样
2. 有账号体系 → 提审时必须填测试号，且测试号能体验全部功能
3. 功能不能只有一个页面一个按钮

## 九、真机验证 9 项（提审前必过）

在开发者工具里点「预览」出码（CLI 预览在 IDE 开着时不动，必须手动点），手机扫码后逐项过：

```
□ 1. 冷启动：杀掉进程重开，首页 3 秒内出内容
□ 2. 每个页面：逐个点进去，没有白屏、没有报错
□ 3. 返回：每个二级页面都能返回，安卓物理返回键正常
□ 4. 按钮：所有按钮点下去有响应，不是死按钮
□ 5. 空态：没有数据时显示空态文案，不是一片空白
□ 6. 权限：拒绝授权后功能降级不崩溃
□ 7. 输入：输入框能输入、能删除、长文本不撑破布局
□ 8. 分享：分享卡片标题和图片正常（如果开了分享）
□ 9. 弱网：飞行模式打开再关，页面能恢复
```

用一个没登录过这个微信的账号测一遍。 审核员就是新用户，你本地缓存会掩盖很多问题。

⚠️ 隐私接口没生效时，绝对不要点提交审核。 审核员点「选择图片」会看到错误弹窗
（内容是「《用户隐私保护指引》还没生效」），等于直接告诉他「这版没配好」→ 驳回。

## 十、一个反直觉的事实

> 前面几次审核通过，不代表下一次能通过，哪怕只改了一个 Bug。

因为后续审核可能发现了之前没发现的违规问题。

**所以：审核通过 ≠ 安全。** 每次提审都按第一次的标准过一遍六项检查。

## 十一、发布

审核通过后**尽早发布**。

```
审核通过 → 立刻点「提交发布」→ 确认线上版本号 → 再开始下一轮迭代
```

⚠️ 审核通过但一直不点发布，线上就还是旧版本 —— **整改等于没做**。
如果之后又提交了新版本审核，之前通过的那个版本可能会消失。

**发布必须等备案通过**（见第三节公式）。备案没下来，点了也发不出去。
