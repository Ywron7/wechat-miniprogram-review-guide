# 小游戏 vs 小程序：审核体系的差异

> 前面七份文档讲的是**小程序**。如果你做的是**小游戏**，有四处硬差异，别照着套。

## 一、先分清你在做哪个

```
小程序  → 工具 / 生活 / 教育 / 信息查询   （类目在「工具」大类下）
小游戏  → 休闲 / 益智                     （类目在「游戏」大类下）
```

**判断标准**：有没有核心玩法循环（关卡、得分、胜负）？
有 → 小游戏。没有 → 小程序。

⚠️ 不要用小程序 + 工具类目去承载游戏玩法。 官方口径：
> 若被平台判定为游戏类内容，应走小游戏体系。

个人主体做带游戏玩法的小程序，既无对应开放类目，又易触碰社交/游戏边界，属高风险行为。

⚠️ 还有一条不可逆：一旦选择了游戏类目，该类目不可修改变更为其他类目（《常见拒绝情形》2.1-3）。

---

## 二、四处硬差异

| 项 | 小程序 | 小游戏 |
|---|---|---|
| **备案与提审的先后** | 备案可在上架发布前完成，提审可并行 | 必须先拿到备案号，才能提交版本审核 |
| **版号** | 不涉及 | 休闲/益智类免版号，但要满足公式（见下） |
| **虚拟支付** | 不涉及 | 个人主体**不支持** |
| **软著** | 不涉及 | **不申请虚拟支付就完全不需要**（见下方说明） |

**最关键的是第一条。** 小程序的备案和提审可以并行，小游戏不行——备案卡住，提审按钮就是灰的。

---

## 三、免版号公式（个人主体）

```
免版号 = 选对类目 + 完成备案 + 不触碰虚拟支付
```

三个条件**同时**满足，个人主体才能顺利上线。

| 条件 | 具体要求 |
|---|---|
| 选对类目 | 个人主体只能选**休闲、益智**等无前置审批类目 |
| 完成备案 | 管局下发备案号，之后才能提审 |
| 不碰虚拟支付 | 不做内购、不卖道具。个人主体本来也开不了 |

**个人主体的优势**：注册免费（企业要 300 元/年认证）、休闲益智类免版号、满足条件后可开流量主。

### 软著那一步怎么过（很多人卡在这）

资质页会问「**是否申请虚拟支付**」，选 **「不申请支付资质」**（纯广告 + 单机变现、无内购）。

选完之后：
```
软著证书        → 标【选填】，直接留空
著作权授权书    → 标【选填】，直接留空
```

页面说明原文：
> 如需开通虚拟支付，则此项为必填材料

所以你不需要软著，也不需要「承诺书替代」——它根本不是必填项。
第二项「著作权授权书」只在代理他人软著或使用他人软著时才需要，个人原创完全留空。

直接跳过，没有任何影响。

## 四、提审表单多两项

在 [06-review-process](06-review-process.md) 那 7 个字段之外，小游戏还多：

### 4.1 适龄提示

显示「审核中」不影响版本提审，微信会合并流转审核。填写参考：

**单选**
```
适龄：8+
画面：非写实
改编：无改编
模式：单人模式
社交：无社交系统
```

**三个输入框**

| 字段 | 限字 | 参考填法 |
|---|---|---|
| 游戏背景 | 10 字内 | `幻想虚构` |
| 游戏主题 | 10 字内 | `休闲解压` |
| 促进功能和价值 | 30 字 | `有助于放松身心、缓解压力，调动积极情绪` |

### 4.2 苹果开发者账号（AppleID）

出现红字 `! 请输入AppleID` 是表单非空校验。

```
填什么：你自己苹果手机登录 App Store 用的个人 Apple ID 邮箱
（如 xxx@qq.com / xxx@icloud.com）
用途： 微信用于校验 iOS 端开发访问权限
要不要花钱：不要。不需要苹果开发者资格（那要 99 美元/年）
要不要苹果设备：不要
```

**苹果开发者信息（选填）**
```
App Store 游戏名称   → 留空
App Store 下载链接   → 留空
```
这两项是给「已有独立原生 iOS App」的厂商互认资质用的，微信纯单机小游戏用不上。

## 五、UI 规范里有一条小游戏专属

《常见拒绝情形》3.6-6：
> 如相关法律法规规定提供服务的界面必须进行特别信息标识的，应予以明确标识。
> 如小游戏必须在游戏开始画面显著位置标明游戏的批准文号、网络游戏出版号以及著作权登记号，
> 全文登载《健康游戏忠告》等。

**这条只在提审小游戏时被查。** 做小程序的完全不用管。

## 六、备案材料多一项

在 [03-icp-filing](03-icp-filing.md) 的材料清单之外，小游戏备案还要：

```
□ 应急联系电话 —— 可填亲友手机号，但不能与管理员手机号相同
```

**这是高频驳回点**，填成一样的会被打回。

---

## 七、截图规范：小游戏要 8 张

小程序 3~5 张就够。小游戏要 **8 张**，分三个模块，且**每个槽位必须是不同的图**（后台有哈希查重）：

```
模块一 · 主要场景（3 张）
1. 主界面大厅（带顶部游戏名、核心操作按钮）
2. 关卡 / 地图界面
3. 设置或特色模式界面

模块二 · 玩法（3 张）
4~6. 三个不同关卡的实际游玩中界面

模块三 · 系统功能（2 张）
7. 货币 / 结算界面
8. 商城 / 图鉴界面
```

**三条硬规则**
```
□ 8 个槽位用 8 张不同的图，不能跨模块复用（后台有哈希查重）
□ 单张 60KB ~ 5MB
□ 顶栏能清晰辨识游戏名称
```

真实驳回原文：
> 所提供的图片质量差，无法辨识图内文本内容

原因是脚本自动截的预览图分辨率偏低（518×920），审核后台压缩后小字边缘发虚，触发 OCR 清晰度阈值。
改法：在开发者工具或真机直接原画质高清截图。

## 八、哪些是通用的

下面这些**小程序和小游戏完全一样**，前面七份文档直接能用：

| 项 | 通用性 |
|---|---|
| 名称规则 | ✅ 完全通用（营销词、通用词、命名结构、改名额度） |
| 隐私与数据 | ✅ 完全通用（接口清单、`scope not declared`、填表模板） |
| 内容安全 5.18 | ✅ 完全通用（小游戏的聊天/昵称/UGC 功能同样受管） |
| 备案的措辞规则 | ✅ 通用（禁词表、经营性判定） |
| 提审节奏 | ⚠️ 部分通用（时长、加急次数通用；前置条件不同） |
| 服务类目 | ❌ 完全不同（见本文第二节） |

## 九、成本：小游戏比小程序慢在哪

前面八节讲规则，这一节讲代价。**做小游戏之前先算这笔账。**

### 唯一的硬瓶颈：备案是前置，不是并行

```
小程序：注册 → 备案（并行）→ 开发 → 提审 → 通过 → 发布（等备案过）
小游戏：注册 → 开发 → 备案 → 拿到备案号 → 才能提审 → 通过 → 发布
```

小程序可以「代码审核和备案同时跑」，谁慢等谁。
小游戏不行——**没备案号，提审按钮就是灰的**，代码写完了也只能等。

### 实测时长

| 环节 | 小程序 | 小游戏 |
|---|---|---|
| 代码审核 | 53 分钟（实测） | 2~24 小时（单机免资质类） |
| 备案 | 可与提审并行 | **必须先过，7~20 个工作日** |
| 从开工到能上线 | 最快 1 周 | **半个月是常态** |

**两个真实样本**

- 一个 83 功能的小程序工具箱：代码审核 53 分钟通过，卡在备案
- 一个改版完成的小游戏：改版全绿、verify 69 项通过，**备案卡了半个月**

**结论**：小游戏的代码不是瓶颈，备案是。你写得再快，也要等管局。

### 所以什么时候该选小游戏

```
✅ 选小游戏
- 核心是玩法（关卡、得分、胜负），不是工具
- 时间不急，能接受 2~3 周上线
- 想走「免版号」这条路省掉版号成本

❌ 别选小游戏
- 目标是「尽快上线验证有没有人要」—— 小程序快一个数量级
- 玩法只是外壳、本质是工具（这种用工具类目做，别碰游戏类目）
```

⚠️ 还有一条不可逆的坑：选了游戏类目就不能改回其他类目（2.1-3）。
如果你还在犹豫「这算工具还是游戏」，先按工具做——工具能改成游戏（重新注册），游戏改不回工具。

---

## 十、小结

小游戏多一道前置门槛（备案必须先过），少一道资质门槛（休闲益智免版号）。

其余的风控点和小程序是同一套。
