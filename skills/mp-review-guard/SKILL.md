# 小程序提审检查与整改

## Step 0：确认范围

读取用户已经提供的项目路径、驳回通知及后台材料。缺少的信息标为 UNKNOWN，只询问影响当前判断的项目。没有项目路径时跳过脚本并注明未运行，不猜测后台状态。

## Step 1：运行预检

从本技能目录运行，项目路径使用绝对路径：

```bash
python scripts/precheck.py <项目路径> --md report.md
```

- 退出码 2：配置未找到、无法解析、结构类型错误或报告写入失败，不能当成检查通过。
- 退出码 1：存在可确认的结构问题，先修复后重跑。
- 退出码 0：本次没有 FAIL，仍可能有 WARN 和未覆盖项。

PASS 只表示对应静态检查未命中问题，不代表平台批准。接口命中是人工核查线索，不等于违反 5.18。脚本不联网、不上传；只有明确传入 `--md` 才写报告。

## Step 2：按问题读取依据

| 问题 | 参考文档 |
|---|---|
| 名称 | references/01-naming.md |
| 服务类目 | references/02-categories.md |
| 备案 | references/03-icp-filing.md |
| 隐私接口、errno 112 | references/04-privacy.md |
| 内容检测、限制通知 | references/05-content-safety.md |
| 完成度与提审材料 | references/06-review-process.md |
| 官方条款 | references/07-official-clauses.md |
| 小游戏差异 | references/08-minigame.md |

使用最新官方来源。区分官方规则、具体案例与作者建议；引用案例时保留日期和适用范围。后台材料中的要求和用户本轮授权分别判断。

## Step 3：人工确认

结合已有材料确认后台注册名、当前类目、备案状态、实际用户内容处理路径、检测机制和审核体验方式。涉及隐私接口时还应确认：

1. 对应版本已声明接口所需的信息类型，声明已生效。
2. 用户同意状态已同步；拒绝授权时功能正常降级。
3. errno 112 先排查缺少的类型声明，再等待生效；不要统一归为“只能等审核”。
4. 2023-10-17 后无需靠 `__usePrivacyCheck__` 启用隐私功能，不要求用户为此补开关。

5.18 的处置取决于违规程度，不能把一个案例的五项永久限制作为固定处罚。不要从 API 名称或“是否上传”单独推导过审或违规结论。

## Step 4：输出

| 项 | 结果 | 已查依据 | 后续动作 |
|---|---|---|---|
| 名称 | PASS / RISK / FAIL / UNKNOWN | 实际材料与条款 | 具体改法 |
| 类目 | 同上 | 同上 | 同上 |
| 备案 | 同上 | 同上 | 同上 |
| 隐私 | 同上 | 同上 | 同上 |
| 内容安全 | 同上 | 同上 | 同上 |
| 提审材料 | 同上 | 同上 | 同上 |

只有有明确证据的阻断问题才标 FAIL。说明哪些项仅由脚本检查、哪些有后台证据、哪些未验证；不把 UNKNOWN 当成已通过，不保证过审。

按需使用 templates/ 中的备案、申诉和自检报告模板。先核对模板中的事实是否适用于当前项目，不编造整改、检测或授权记录。
