## 一、名称

```
□ 已核对后台注册名称与宣传表述，没有把单字「最」当作禁词
□ 名字里没有通用品类词：工具箱/工具/助手/大全/导航/查询/平台
□ 结构是「造词/品牌词 + 功能词」，不是「功能词 + 品类词」
□ 名字里没有特殊行业词：社区/保险/教育/医疗/金融
□ 简介里能找到名字里的词，两者意思一致
□ 后台「当前还能修改 N 次」已截图，N = ____（必须 ≥ 1）
□ 4 处显示名已同步：app.json 标题 / 首页 banner / 分享标题 / 关于页
```

**官方依据**
- 1.1-2：不得含商业化用语、广告法禁词
- 1.2.1-3：不得以通用归纳类命名，须两个词以上组合，**审核人员可主观判断**

## 二、类目

```
□ 核心功能能在个人开放类目清单里找到一行（找不到就停，改方向）
□ 每个已填类目，首页 2 次点击内能到达对应功能页
□ 对应页面能真的完成该类目的服务，不是空壳
□ 没有「传播 / 分享 / 公开访问 / 他人可见」功能
□ 已填类目数 = ____（≤ 5）
□ 本月剩余修改次数 = ____
□ 功能落位表：每条功能恰好出现一次（不是总数对就行）
```

**官方依据**
- 2.1：类目对应页面核心内容必须一致，不得隐藏、不得多次跳转
- 2.1.3：选了游戏类目不可改为其他类目
- 3.1-2：所有类目功能须首页直达或 2 次点击到达

## 三、备案

```
□ 备案已提交（不是「准备提交」）
□ 备案状态：☐ 审核中 ☐ 已通过 ☐ 被驳回（驳回原因：__________）
□ 备注里没有任何禁词：电商/商城/交易/付费/会员/广告/推广/商用/卖家
□ 备注里没有使用场景描述（「电商主图」「商用素材」「卖家批量处理」）
□ 地址精确到门牌号，与身份证一致
□ 备注写的功能 = 小程序实际有的功能
□ 手机号能接短信/电话核验
```

**官方依据**
- 备案可与开发并行，**须在上架发布前完成**
- 备案信息与小程序信息不一致 → 平台可警告、封禁功能、强制注销备案

## 四、隐私

```
□ 跑过 grep，列出所有隐私接口调用：____________________
□ 每个接口都对应到后台隐私指引里勾选的一项
□ 对应版本所需的信息类型已声明并生效
□ 现网与提审版本没有混用，用户同意状态已同步
□ 用户拒绝授权时，功能降级不崩溃
□ 没有在未授权情况下显示头像/昵称
□ 有定位功能的话，提供了关闭开关
□ 有账号体系的话，有可发现的「退出」入口
```

**官方依据**
- 3.4-1：收集使用数据须明确告知用途、经同意、范围内使用
- 3.4-5：未经授权不得显示头像、昵称
- 3.5-5：有账户系统须提供易于发现的「退出」

## 五、内容安全（5.18）

```
□ 产品会处理用户提供的内容（图片/文字/音频/视频）：☐ 会 ☐ 不会
□ 处理结果会离开小程序（存相册/导出/分享）：☐ 会 ☐ 不会
□ 已按用户内容的实际数据流核对过滤机制，未仅凭 API 名称判断
□ 没有任何用户可见的内容列表（广场/历史/他人作品）
□ 没有用户输入文字生成图片的功能（水印/字幕/文字转图）
□ 没有分享图、二维码分享、短链分享
```

**官方依据**
- 3.2-11：服务提供者**必须**提供过滤不当内容的措施
- 5.18 内容安全：五项永久限制（分享 / 被搜索 / 跳转 / 短链 / 扫码）

**三条路，没有第四条**
1. 接服务端内容安全接口（要钱、要后端、要改隐私话术）
2. 改产品形态，让内容不离开本机也不产出新内容
3. 不做这个形态

## 六、提审节奏

```
□ 没有「即将上线」「敬请期待」「功能开发中」字样
□ 不是「只有一个页面一个按钮」的极简品
□ 有账号体系 → 已准备测试号（账号 + 密码，可体验全部功能）
□ 真机验证 9 项已过（冷启动/逐页/返回/按钮/空态/权限/输入/分享/弱网）
□ 用没登录过的微信账号测过一遍
□ 提审时间选在工作日 9:00-11:00（个人主体审核 9:00-21:00）
□ 加急审核 3 次/年，留到关键时刻，不用在第一次
```

**官方依据**
- 3.3-1：须是完成品，不可为测试版
- 3.3-4：有账号体系须提供测试号
- 3.1-5：功能不能过于简单

## 提审后（重要）

```
□ 提审后到出结果之间：不动名称、不动简介、不动类目、不动 logo、不重新上传
□ 出结果当天处理：一次只改一项，不要顺手改别的
□ 审核通过：立刻点发布（拖着不发布，后续提审可能让通过的版本消失）
```

官方 5.18 按违规程度阶梯处置；原项目的五项永久限制不得当作所有项目的固定规则。
