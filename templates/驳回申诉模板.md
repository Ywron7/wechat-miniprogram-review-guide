# 驳回申诉模板

申诉通过率不高。但申诉的真实价值不一定是解封，**而是拿到那句官方口径**。

## 用之前先判断：这次该不该申诉

```
□ 驳回理由是「名称通用词 / 营销词」→ 不要申诉
   申诉不能推翻通用词判定，只有商标能。直接改名。

□ 驳回理由是「类目不符」→ 不要申诉
   换类目或砍功能，申诉没用。

□ 驳回理由是「功能不完整 / 无法体验」→ 不要申诉
   自己修，申诉只会浪费时间。

□ 驳回理由是「未设置内容过滤机制」（5.18）→ 可以申诉
   这是唯一值得申诉的类型，因为它涉及产品形态定性。

□ 驳回理由是误判（比如你的功能确实是工具，被判成社交）→ 可以申诉
   这时申诉的价值是把定性纠正过来。
```

**硬规则**
- 申诉入口**两次不通过即关闭**
- 不要拿猜测去试第一次
- 第二次必须有新增证据，不能重复同一套说法
- 申诉期间不要改动小程序任何配置（会打断审核）

---

## 三段式结构

### 第一段 · 摆事实，给可核验的东西

审核员每天看几百条申诉，**能被核验的陈述才有分量**。

```
本小程序零网络调用，后台服务器域名四项全空，平台可自行核验，
运营方从未获得任何图片。
```

要点：
- 说「平台可自行核验」，不要说「我说的都是真的」
- 给具体的、后台能查的东西（域名配置、接口调用记录、代码包）
- 不要抒情，不要解释动机

### 第二段 · 说明扩散链路已不存在

如果处置已经封了分享/搜索/扫码，这一条很有力：**惩罚已经超过了违规的实际影响**。

```
输出只写用户本机相册，且分享/短链/二维码/跳转已被封，
扩散链路已不存在，继续封「被搜索」惩罚的是获客不是违规。
```

要点：
- 把「我没有传播」和「平台已经封了传播」两件事分开说
- 指出继续封某项 = 惩罚的是获客，不是违规

### 第三段 · 把整改方向变成向他们要口径

**这是整个申诉里最关键的一段。**

```
愿继续收紧可写入用户文字的功能，但接入识别接口需上传用户图、
与已公示的「不上传服务器」隐私指引直接冲突，
请平台明确「不采集图片前提下可接受的整改方式」。
```

为什么这样写：
- 你承认愿意整改（态度上无可指摘）
- 你指出两条要求互相冲突（逻辑上他们必须回应）
- 你把「我怎么改」变成「你告诉我怎么改」

就算不解封，也能拿到一句可执行的官方答复。**那句话本身就是资产。**

## 完整模板（可直接改用）

```
【申诉主题】关于「未设置过滤违法、违规等不当信息内容的机制」的整改说明

【第一段 · 事实】
本小程序（AppID：__________）自上线以来，零网络调用，后台「服务器域名」
四项配置全部为空，平台可自行核验。所有图片处理在用户设备本地完成，
运营方从未获得、存储、传输任何用户图片。

【第二段 · 扩散链路】
小程序输出仅写入用户本机相册，不存在任何站内内容展示、内容列表或公开访问入口。
目前分享、被搜索、跳转其他小程序、短链接、二维码五项功能均已被限制，
扩散链路已不存在。继续限制「被搜索」，实际惩罚的是获客能力，而非违规传播。

【第三段 · 整改方案与请示】
我方愿继续收紧可写入用户文字的功能（当前已下架水印、字幕等 ____ 项功能）。
但接入内容安全识别接口，需将用户图片二进制上传至服务端，
这与本小程序已公示的「不上传服务器、不收集用户信息」隐私指引直接冲突，
且会引入超出必要范围的个人信息收集风险。

请平台明确：在不采集用户图片的前提下，可接受的整改方式是什么。

【附件】
1. 后台服务器域名配置截图（四项为空）
2. 代码包网络请求扫描结果
3. 隐私指引公示截图
4. 已下架功能清单
```

## 如果两次都被驳回

申诉入口关闭后，剩下的路只有两条：

**一、改产品形态，重新做**
- 要么接服务端内容安全接口（要钱、要后端、要改隐私话术）
- 要么让产品彻底不产出新内容（比如只做只读工具）

**二、放弃这个号，但不要复制同一个形态**
> 5.18 判的是**产品形态**，不是运气。换号必然重演。

---

## 一句话

申诉不是为了赢，是为了**逼他们给一句可执行的话**。

拿到那句话，你就知道下一步该怎么改；拿不到，至少你知道这条路走不通了。
