## 30 秒开始

```bash
git clone https://github.com/Ywron7/wechat-miniprogram-review-guide.git
cd wechat-miniprogram-review-guide

python scripts/precheck.py <你的小程序项目根目录>
```

无第三方依赖，Python 3.8+ 即可。加 `--md report.md` 把报告写到文件。

支持两种项目结构：

| 类型 | 配置文件 |
|---|---|
| 原生小程序 | `app.json` |
| uni-app | `pages.json` + `manifest.json`（支持 JSONC 注释与尾逗号；不支持完整 JSON5） |

退出码 `0` 表示本次没有 FAIL（可能仍有 WARN）；`1` 表示有可确认的结构问题；`2` 表示目录、配置或报告写入错误，未完成检查。CI 应同时拦截 `1` 和 `2`。政策词表只输出 WARN，不能作为自动过审判据。

## 给 AI agent 用

这个仓库是给人读的。如果你想让 AI 直接执行检查，去 [Releases](../../releases) 下 `mp-review-guard.zip`。

解压后把文件夹放进 skills 目录（如 `~/.claude/skills/`、`~/.qoder/skills/`），AI 会读 `SKILL.md` 按 Step 0~4 执行。

```
SKILL.md              执行流程（前置检查 → 跑脚本 → 读文档 → 人工确认 → 固定输出）
references/           六项检查判据（名称/类目/备案/隐私/内容安全/提审节奏 + 条款索引）
scripts/precheck.py   静态预检脚本
templates/            驳回申诉、备案备注、自检报告
```

两者定位不同：

```
这个仓库   → 人读，完整规则 + 条款索引 + 案例
skill 包   → agent 执行，固定流程 + 固定输出格式
```

全部内容都在这个仓库里，没有保留版本。

## 常见问题

**小程序名称被驳回，说「涉及以通用词命名」，怎么办？**

改名。申诉不能推翻通用词判定，只有商标能，而个人申请商标要 6~12 个月。
个人主体无商标时，名称必须是「造词或品牌词 + 功能词」，不能是「功能词 + 品类词」。
详见 [01-naming](docs/01-naming.md)

**个人主体能做哪些服务类目？**

只有 9 大类：物流、教育、交通、生活、餐饮、旅游、工具、商业、体育。工具类下含记账/日历/天气/办公/图片处理/计算器/报价比价/信息查询/预约报名/健康管理/备忘录。
没有游戏、社交、社区、论坛、直播、笔记、问答。
详见 [02-categories](docs/02-categories.md)

**备案备注写了什么会被驳回？**

任何能联想到「赚钱」的词。真实案例：备注写「适合报名照片、电商主图、邮件附件」，被判涉及经营性驳回，「电商主图」最致命。
个人主体只能写「个人自用 / 学习 / 便民工具」，并加一句「不涉及任何交易、付费或经营活动」。
详见 [03-icp-filing](docs/03-icp-filing.md)

**被 5.18 永久限制了，还能申诉吗？**

是否可申诉及入口状态以后台通知为准。本项目曾收到内容分享 / 被搜索 / 跳转其他小程序 / 短链接 / 二维码五项永久限制；官方 5.18 按违规程度阶梯处置，并非所有项目固定五项永久限制。
申诉的价值不一定是解封，是拿到平台口径——第三段写成「请平台明确可接受的整改方式」。
详见 [05-content-safety](docs/05-content-safety.md)

**隐私接口报 `scope not declared`（errno 112），清缓存换手机都没用？**

先检查接口所需的信息类型是否在对应版本声明；缺少就补齐，已补齐再检查生效状态。官方错误说明列明补充声明有约 5 分钟的生效等待。还需处理用户同意，不能只看后台审核状态。
2023-10-17 后，不论是否配置 `__usePrivacyCheck__`，隐私功能都会启用。
详见 [04-privacy](docs/04-privacy.md)

**「本机处理、不上传服务器」能过内容安全吗？**

不能仅凭“本地处理”确定合规，也不能据此确定违规。本项目的纯本地图片镜像功能曾收到 5.18 处置；这是一个案例。实际产品还应核查用户内容、展示与保存传播路径、检测机制，并按平台反馈验证。
详见 [05-content-safety](docs/05-content-safety.md)

**小程序和小游戏，审核上有什么硬差异？**

最关键一条：小游戏必须先拿到备案号才能提审，小程序可以与备案并行。另外小游戏个人主体只能选休闲/益智类目，不支持虚拟支付，提审多「适龄提示」和「AppleID」两项。
还有一条不可逆：选了游戏类目就改不回其他类目。
详见 [08-minigame](docs/08-minigame.md)

**提审多久能出结果？加急有几次？**

本项目的一次提审到发布记录为 53 分钟，两次名称驳回为当天；单个项目的样本不能代表所有项目的通常时长，排期应参考平台当前说明。
加急审核个人主体每年 1 次（非个人主体 3 次）。
详见 [06-review-process](docs/06-review-process.md)

**提审前到底要检查哪些？**

六项检查：名称、服务类目、ICP 备案、隐私、内容安全、提审节奏。任何一项 FAIL 都别提审。
一页纸打勾版见 [速查清单](docs/00-quick-checklist.md)，或者直接跑 `python scripts/precheck.py <项目路径>`。

## 适用范围与免责

适用：

- 个人主体、无商标、零预算，第一次做微信小程序
- 已有一个能跑的代码，卡在审核/备案/隐私/内容安全
- 被驳回、被限制，需要知道下一步改什么

不适用：

- 医疗、金融、直播、电商平台等需要前置许可的类目（个人主体基本拿不到）
- 纯代码开发问题
- 企业主体的特殊资质流程

不保证过审。官方原文写得很清楚：「当无法判断时，审核人员可主观判断」。这份清单是把概率拉高，不是给确定结论。

## 验证和生成 skill 包

脚本只维护 `scripts/precheck.py` 一份；文档维护在 `docs/`，模板维护在 `templates/`。`skills/` 下只保存两个包的执行流程。请修改这些源码后统一构建，不手改解压后的副本。

```bash
python -m unittest discover -s tests -v
python scripts/build_skill.py
```

构建输出为 `dist/mp-review-check.zip`（清单与文档）和 `dist/mp-review-guard.zip`（另含脚本与模板）。完整包内的预检脚本与仓库脚本字节一致，两包均附 LICENSE 和 BUILD.json，后者记录 VERSION、源提交及文件 SHA-256。

发布时先确保工作区干净、VERSION 与标签一致，再构建并上传 ZIP；发布后重新下载核验 BUILD.json 与脚本摘要。移动标签不会重新生成已上传附件。

静态扫描支持直接 wx/uni 调用、部分字面量属性调用、分享钩子和隐私组件。它不是完整 JS/TS 解析器，别名、动态调用、宏生成代码和后台状态仍需人工确认。界面扫描主要读取模板文本，不追踪运行时生成文案。
