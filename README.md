# 微信小程序提审避坑指南

> 被驳回两次、被 5.18 永久限制过一次之后，把踩过的坑写成了一份可自查的清单。

微信小程序的审核驳回成本不是重做，是**排队时间**。一次驳回 = 一天，一次永久限制 = 整条线归零。

这份指南不教怎么写代码。它只干一件事：**在你点「提交审核」之前，把能杀掉你的那几项找出来。**

---

## 这份东西从哪来

不是整理别人的教程，是一个真实项目从开发到上线到被封的全过程记录：

| 事件 | 实况 |
|---|---|
| 名称驳回 #1 | `图片转换免费工具箱` → 「涉及营销商业化词，命名不规范」，**当天驳回** |
| 名称驳回 #2 | `图片转换工具箱` → 「涉及以通用词命名」，**当天驳回** |
| ICP 备案驳回 | 备注里写了「电商主图」，被判**涉及经营性** |
| 提审到上线 | 14:15:40 提交 → 15:08:39 发布，**53 分钟** |
| 5.18 处理 | 五项**永久限制**（分享/被搜索/跳转/短链/扫码），触发方式是**用户投诉** |
| 申诉 | 三次被驳，申诉入口两次不通过即关闭 |

所有判据都能追到官方原文，所有实测都带时间戳。**没有一条是推测。**

---

## 它不解决什么

诚实说明，避免误用：

- **不保证过审。** 官方原文写得很清楚：「当无法判断时，审核人员可主观判断」。这份指南是把概率拉到足够高，不是给你一条确定的线。
- **不覆盖特殊资质类目。** 医疗、金融、直播、电商平台这些需要前置许可的，个人主体基本拿不到，不在本文范围。
- **不是代码教程。** 假设你已经有能跑的代码，卡在审核这一关。
- **规则会变。** 本文基于 2026 年的规则和实测。看到明显过时的条目，欢迎提 issue。

## 快速开始：先跑脚本

```bash
python scripts/precheck.py <你的小程序项目根目录>
```

输出一份 PASS / WARN / FAIL 报告。不联网、不上传、不修改任何文件。

扫四类东西：

| 扫什么 | 对应哪一闸 |
|---|---|
| 应用名、各页标题、tabBar 文字里的营销词/通用词 | 名称 |
| 高危 API（分享、相册、头像、位置、手机号、剪贴板） | 隐私 + 内容安全 |
| 内容产出与外流路径（canvas 导出、存相册、分享） | 内容安全 |
| 未完成品痕迹（「即将上线」「测试版」）、包体积 | 提审节奏 |

支持 `app.json`（原生）和 `pages.json`（uni-app）两种格式，含 JSON5 容错（HBuilderX 生成的 manifest 带注释）。

退出码：`0` 全过或只有 WARN，`1` 存在 FAIL。

## 六道闸速览

```
① 名称      个人主体无商标 → 不能是「功能词 + 品类词」
② 类目      功能不在个人开放清单里 → 怎么改都过不了
③ 备案      备注里能联想到「赚钱」→ 涉及经营性，必驳
④ 隐私      调了隐私接口 → 后台指引必须「已通过」，审核中一定报错
⑤ 内容安全  处理用户内容并产出新内容 → 平台就要求你做识别
⑥ 提审节奏  提审后别动基本信息；一次只改一项
```

**任何一项 FAIL，都不要提审。** 提审不会帮你发现问题，只会帮你排队一天。

## 三个最反直觉的事实

**一、`__usePrivacyCheck__` 已经失效了。**
网上大量教程让你在 `app.json` 里加这个字段。它只在 2023-09-15 ~ 2023-10-17 的过渡期有效。
2026 年真正决定接口能不能调的，只有后台《用户隐私保护指引》是否审核通过。

**二、「本机处理、不上传服务器」不构成豁免。**
平台的安全模型三个「不看」：不看语义、不看是否上传、只看「用户内容 → 视图节点」这条链上有没有检测机制。
你不上传，不代表你没处理内容。

**三、加急审核个人主体每年只有 1 次。**
网上大量文章写「3 次/年」——那是非个人主体的口径。
